# Agent Memory For gzhpublisher

This file is the project-local memory layer for AI agents working in this
repository. Keep project facts here; keep broad personal preferences in global
memory only when the user explicitly confirms them.

## Operating Principles

- Project memory comes first. Do not move gzhpublisher-specific facts into global
  memory unless the user confirms they are cross-project preferences.
- At the end of a meaningful phase, propose memory/doc/skill updates before
  applying them.
- Promote a lesson to a skill rule only after it appears twice, unless it is a
  hard user red line or a safety/compliance rule.
- Prefer editing existing skills over creating new skills.
- Keep `SKILL.md` files lean; put detailed playbooks in directly linked
  `references/` files.

## Project Red Lines

- WeChat article author is fixed as `桥博士`. Never use `author: 宽论`.
- WeChat publishing uses `theme_id: "orangeheart"`.
- Publish through `mcp__wenyan-mcp__publish_article` with only `file` and
  `theme_id`.
- Do not publish if audit, compliance, local-image, or author blockers remain.
- Kuanlun/QMACD content must stay in quant-analysis education and methodology,
  not investment advisory, stock tips, or guaranteed results.

## Memory Layers

- Project memory: `AGENTS.md`, `README.md`, `docs/`, and repository skills.
- Knowledge wiki: `llm-wiki` under the configured wiki path for external sources,
  research synthesis, and reusable method knowledge.
- Preference memory: only stable user preferences and red lines that have been
  confirmed as reusable outside this repository.

## Stage-Close Protocol

When a phase finishes, especially after a push, publishing workflow fix, skill
update, or repeated mistake:

1. Read `docs/self-evolution-memory-system.md`.
2. If `.git/self-evolution-pending.md` exists, treat it as a stage-close
   reminder generated by Git hooks.
3. Run the `self-evolution` skill.
4. Output a proposed memory update list grouped as:
   - project memory
   - wiki knowledge
   - preference memory
   - skill candidates
5. Wait for user confirmation before changing memory or skills, unless the user
   has already asked to implement those exact changes.

## Installing This In New Projects

From this repository, run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install_self_evolution_hooks.ps1 -TargetRepo "C:\path\to\project" -InstallPolicy
```

Use `-Force` only when intentionally overwriting an existing hook script or policy
document.
